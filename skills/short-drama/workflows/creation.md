# 创作与会话续接

提交使用 [short-drama +submit-run](../commands/submit-run.md)。首次新建；续写、修改或回复问题复用原 thread_id，并保存新 run_id。原样传递用户文本，不替后端创作。单会话只绑定一个剧本，缺少必要输入时先询问。

## 业务内容查询

用户询问当前项目的角色、场景、外观、画布节点、分镜片段、设定、关联、数量或资产状态时，原样通过 `short-drama +submit-run --thread-id THREAD_ID --message "用户原始问题"` 提交到当前会话，记录新 run_id，并用 `get-thread` 获取本次服务端回答。保留用户指定的范围，例如“画布中的场景”不能替换成“剧本提到的场景”。缺少目标且上下文无法确定时才询问，不猜会话或资产 ID。

- 宿主可忠实整理服务端回答，但不自行补全、合并去重、计算数量或解释未返回的业务关系。历史回复只用于定位上下文，不代替本次查询。
- 不通过文件名、目录、文件数量、内部 JSON、已下载剧本或网页内容推断业务信息；不切换到浏览器、其他技能或自行调用 API 作为内容查询兜底。网页入口仍可供用户查看。
- 文件读取仅用于用户明确要求的文件内容查看，或规定范围内的下载、校验、预览和交付。回答须限定为该文件的内容，不据此宣称当前项目或画布状态。“片段1内容是什么”是业务内容查询，不等于请求下载或解析 `storyboard.json`。
- 纯内容查询只授权读取和回答，不授权重新分析、补资产、修改或生成。混合请求（如“看看有哪些场景，把缺的图补齐”）仍原样提交，按用户已明确授权的范围执行，不重复确认；服务端提出超出已有授权的操作时，说明所需动作并等待用户授权。不要为了回答问题自行推进创作阶段；若服务端已意外执行未授权操作，报告实际情况，不继续扩大操作。
- 服务端查询失败、缺项、范围不符或回答与工具错误矛盾时，报告已确认的信息和无法确认的部分，不以宿主推断补齐，也不把 Run 完成或笼统的“工具已完成”等同于资产生成成功。

进度查询仅使用 `get-thread`；文件取件使用 `list-thread-file` 和 `download-result`，不为这两类请求新增 Run。业务内容查询提交后按 [轮询与文件交付](poll-and-deliver.md) 跟进本次 Run，确认终态后展示最终回答，不将中间说明当作最终结果；后端提问、明确失败、用户停止或超时按轮询规则结束。纯查询不自动进入下一创作阶段。

## 任务页与宿主衔接

提交后立即展示真实 web_thread_link，并优先使用当前宿主实际提供的内置浏览器或页面打开能力打开。豆包、Codex Desktop、WorkBuddy、TRAE 各用自己的能力，不套用其它宿主的工具名。无法自动打开时说明原因并提供手动链接，继续 CLI 查询和交付；网页只供查看、确认和调整，不代替 CLI 取件。

豆包登录续接按 [授权说明](../commands/auth.md) 处理；不要重发用户原需求而创建重复会话。

## 短剧主流程顺序

短剧创作按以下主流程推进。用户侧 Agent 在展示后端 Agent 的表单、问卷、选项或确认问题时，必须先参考这个顺序判断当前阶段和合理下一步。

1. 剧本准备：上传剧本、AI 生成剧本、编辑、改编或续写。
2. 确认当前剧本并分析：向用户确认使用最新剧本后进入分析；角色、场景分析由该分析流程自动衔接，不作为用户侧独立阶段。
3. 风格确认：确认短剧风格推荐。
4. 角色与场景图片：按已确认风格生成本次范围所需的角色与场景图片，详见下方图片前置检查。
5. 故事版：生成或修改故事版、分镜和相关素材。
6. 片段视频：生成或重生成片段视频。
7. 完整视频：合成完整视频。

剧本标准化是风格确认后的可选操作，只在用户明确希望标准化整理、旁白改编或统一表达时执行。主流程是能力范围，不是每次必须从头执行的清单；按用户意图和当前真实资产进入对应步骤。

## 角色与场景图片前置检查

在短剧主流程中，生成故事版和片段视频前，先完成本次范围所需的角色与场景图片生成。角色、场景分析或文字设定完成，不等于图片已生成完成。这里的完成确认是核对服务端结果，不新增用户确认步骤；授权和创作偏好确认仍按既有规则执行。

- 在原会话内按已确认风格和用户授权范围推进图片生成；已有图片可复用时不重复生成，只补所需的缺失图片。不自行补写角色外观、场景设定或图片提示词。
- 图片是否生成完成以服务端回答为准；状态不明确时，按业务内容查询规则核对，不从文件名、文件数量或内部文件推断。图片仍在生成时等待原任务，失败或提交结果不确定时按轮询流程处理，暂不推进短剧主流程的故事版和片段视频生成。
- 用户只要求剧本、解析、查询、取件或独立素材时，保留原有任务范围和独立素材边界，不额外推进整剧制作。图片生成沿用既有授权规则，已获授权不重复确认。

## 独立素材创作边界

用户要求直接生成或编辑图片、视频、音频、画布节点或画布素材时，先确认当前会话已完成剧本解析/分析。未完成时，先推进剧本准备、确认当前剧本并分析；不要绕过剧本解析直接进入素材生成。

完成剧本解析后，可按用户原始需求提交给服务端处理。服务端可直接完成这类独立素材创作，不要求继续完成风格确认、故事版或片段视频；产物也不会因为生成成功就自动绑定、替换或推进短剧项目。只有用户明确要求把产物应用到项目时，才回到对应项目流程，核实目标范围并按授权规则执行。

## 表单与问卷选项处理原则

后端 Agent 通过 `readable_text` 发出表单、问卷、选项、按钮或询问用户时，用户侧 Agent 不要机械原样转述所有选项。先结合短剧主流程顺序清洗选项，再把合理、必要、当前可执行的流程项呈现给用户。

- 保留当前阶段的确认项，以及不会跳过必要阶段的下一步流程项。
- 剔除跳过必要阶段的选项。例如未确认当前最新剧本前，不应让用户直接进入“剧本分析”；未完成风格确认前，不应让用户直接进入故事版；不满足图片前置检查时，不应进入故事版或片段视频生成；未确认故事版和片段视频范围前，不应进入完整视频合成。
- 剔除倒退到无关阶段的选项。只有用户明确要求返工、修改或重新生成时，才展示回退选项。
- `剧本标准化` 是可选阶段，只能出现在“风格确认”之后、“故事版”之前。不要把它包装成任意阶段都可以跳过或补做的通用选项。
- 不替用户决定创意内容，例如风格、剧情方向、角色设定、镜头方案。只能清洗流程选项，不能代替用户选择创作偏好。
- 如果服务端问题混入跨度过大的多个流程选项，重新组织成当前阶段可回答的问题，并说明已按主流程剔除不合理或跳跃选项。

## 提问与用户回复

收到后端的表单、问卷、选项、按钮或问题时，先按上述阶段清洗流程选项，不替用户决定创意。按当前宿主实际提供且模式允许的能力提问：

- 豆包：使用已暴露的结构化提问、确认或表单能力，不臆造工具名。
- Codex：`request_user_input` 或 `request_user_input_async`，仅在当前模式允许时使用。
- WorkBuddy：已提供时使用 `ask_user_question`。
- TRAE 或其它宿主：检查实际工具；无同类能力时用普通聊天。

以上所有宿主均适用：提问工具未暴露或当前模式不允许调用时，退回普通聊天，清晰列出问题及可选项，并说明等待用户回复后继续；不因缺少工具而代答或跳过确认。

提问后等待用户回复；不能代答、默认选择或在超时后继续。消耗 credits 的新阶段未获用户明确执行确认时先确认，已有明确授权不重复索取。

收到回复后，原样通过同一 thread_id 提交，记录新 run_id；不要新建会话，不再绑定第二个剧本。随后按 [轮询与文件交付](poll-and-deliver.md) 查询进展和文件。旧 Run 的同一问题只展示一次，不能当成新问题反复打断用户。
